# Wydzielenie strony głównej — pomiar buildów

Bez zmiany URL, tła ani treści. HomePage ładowana przez React.lazy, jak pozostałe
strony. Wejście bezpośrednio do katalogu lub formularza konta nie pobiera jej kodu.

Pomiar: Vite produkcyjny build przed/po na main 9565f7c z testową konfiguracją API.
Sumy modułów wymaganych dla wejścia i danej trasy według manifestu, bez CSS/obrazów.
Gzip liczony lokalnie Python gzip na każdym pliku oddzielnie, nie transfer Netlify.

| Trasa | JS przed | JS po | Gzip przed | Gzip po |
|---|---:|---:|---:|---:|
| /peaks | 553715 B | 523158 B | 164591 B | 156176 B |
| /login | 544158 B | 496200 B | 161612 B | 147608 B |
| / | 537380 B | 538187 B | 158342 B | 160648 B |

Kompromis: strona główna potrzebuje dodatkowego modułu i około 2,3 kB więcej gzip.
Nie twierdzimy, że przyspiesza jej LCP. Korzyść dotyczy bezpośredniego wejścia na
inne strony; po odwiedzeniu strony głównej kod jest już w cache.

Lokalny produkcyjny build w Chromium 390/1440 px: brak pobrania HomePage na /login,
pobranie dopiero po przejściu na /, FAQ wyrenderowane, brak błędów pageerror.
Surowe wyniki: route-size-comparison.json oraz route-smoke.json.

Nie jest to pomiar terenowych Core Web Vitals ani benchmark opóźnień sieci.
Dalszy pomiar LCP/CLS/INP wymaga reprezentatywnych urządzeń i interakcji.
Zmiana bazuje na PR tłumaczeń panelu, który zawiera niezależną poprawkę wyścigu
resetowania filtrów wykrytą podczas testów między przeglądarkami.
